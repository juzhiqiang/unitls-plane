# AI 电商试衣设计

## 目标

在 Utils-Plane 增加独立的 AI 电商试衣模块，让用户用真实商品图或服饰灵感图库，搭配系统模特或个人照片、姿势参考，生成电商展示图。首期继续使用项目现有 OpenAI 兼容生图服务、任务队列和文件存储。

## 已确认需求

- 试衣是独立模块和独立任务类别，历史记录可单独识别。
- 支持真实商品图、姿势图库、服饰图库、模特图库，并允许用户上传自己的人像。
- 真实商品试穿与灵感穿搭都要支持；两种用途在界面和结果说明中区分。
- 试衣和普通 AI 生图共用每日生图总额度。
- 继续使用现有 AI 生图 API，不在首期接入专用 VTON 模型。
- 借鉴开源项目的素材分组、参考图角色和提示词组装，不默认复制其图片素材。

## 用户流程

1. 进入独立的「AI 电商试衣」页面并选择「真实商品试穿」或「穿搭灵感」。
2. 选择系统模特，或上传个人照片。
3. 真实商品试穿时上传商品实拍；穿搭灵感时从服饰图库选择目标服装。
4. 可选姿势参考。真实商品模式允许添加一张灵感服饰作为弱优先级辅助参考，但明确商品实拍才是商品款式、颜色和纹理的目标来源。
5. 服务端按固定角色顺序组装参考图和提示词，创建异步任务；返回结果、进度、错误和共享额度状态。
6. 用户在独立试衣历史中查看输入与产物，并下载或再次生成。

## 体验与质量约束

- 参考图最多 4 张：人像、目标服装、姿势和可选辅助服饰参考；校验数量与角色，不允许引用不属于当前用户的上传文件。
- 姿势、人物、服饰素材要明确标注用途、来源和许可；未确认可商用/再分发的素材不得打包或热链复用。
- 不承诺通用生图模型精确复现商品细节。真实商品结果明确标为 AI 生成展示图，首发前用不同品类的 SKU 样本评估颜色、图案、剪裁和配饰偏差。
- 用户上传的人像使用现有私有文件生命周期与访问控制；删除试衣历史时按既有任务/文件清理规则处理。
- 中英文文案同步；不因开发环境或工具链改动更新用户可见 changelog。

## 非目标

- 首期不训练模型、不部署专用 VTON 模型、不承诺尺寸/版型/面料的真实试穿准确性。
- 首期不建设面向运营人员的图库管理后台；图库通过经授权的种子数据和对象存储交付。
- 首期不做批量 SKU 上架、品牌商品目录同步或多商品搭配。

## 架构决策

- 前端独立路由与组件，不把试衣状态塞入普通生图会话。
- 数据层新增 `image_try_on`
  任务类型，复用任务表和任务队列；输入配置只存模式、参考角色与提示词语义，不存敏感图片 URL。
- 生图处理复用现有
  `ImageGenerationService`；新增专用配置 schema 与提示词组装函数，复用现有参考图读取、图像预处理和产物标记流程。
- 姿势、服饰、模特参考项通过独立的试衣图库表/服务和只读 API 提供；文件存放到现有公开只读素材桶时，仅限许可明确的素材，必要时复用项目既有图库对象存储约定。
- 每日额度统计将 `image_generate` 与 `image_try_on` 作为同一额度组计算，并由服务端原子校验。
- 任务列表按图像类别包含新类型，前端任务筛选和类型标签能将试衣单独呈现。

## 待实现细节

- 人像、姿势、商品图和灵感服饰的优先级及提示词模板由固定服务端逻辑控制，用户附加说明作为补充，不覆盖商品图角色说明。
- 图库首批素材规模与来源在实施时以许可证审查结果决定；授权不足时先以少量自有素材启动，不阻塞上传真实商品图流程。
- 共享额度的重试、失败和并发计数遵循现有生图策略；测试需验证两个任务类型跨模块合并计数。
