# 图片压缩超大文件处理设计

## 背景

图片压缩页当前将上传区的 `maxSize` 固定为 50 MB。超过该值的图片会被 `react-dropzone`
在前端直接拒绝，并显示未经本地化的 `File is larger than 52428800 bytes`，文件无法进入本地压缩流程。

服务端上传并非统一支持 250 MB，而是使用共享额度：游客 10 MB、登录用户和 Pro Preview 50 MB、Pro 100
MB、团队 150 MB、私有部署 250 MB。API 的传输层上限为 250 MB，业务层仍按当前用户额度校验。

## 目标

- 图片压缩页允许最大 250 MB 的静态图片进入本地处理流程。
- 文件超过当前账号的服务端上传额度时，仍可使用本地压缩。
- 超过服务端额度的文件不能误进入上传流程，并显示中英文可读提示。
- 超过 250 MB 的文件继续在选择阶段拒绝，并显示本地化的大小限制提示。
- 不改变其他工具页的上传限制，也不提高 API 的套餐额度。

## 方案

### 上传与处理边界

图片压缩页使用 250
MB 作为浏览器本地处理入口上限。该值与服务端最高传输额度一致，避免无限制接收可能耗尽浏览器内存的文件。

页面根据当前会话用户的 `plan`、`role` 和 `id`，通过共享 `getLimit(..., 'upload.maxFileSize')`
计算服务端额度。选择的任一文件超过该额度时：

- 处理方式推荐“本地”。
- 服务端选项不可用，旁边显示当前服务端单文件额度。
- 已经处于服务端模式时自动切回本地，避免开始处理后才失败。

文件不超过服务端额度时，保留现有小文件优先本地、大文件推荐服务端的规则。

### 错误文案

扩展共享 `FileDropzone`，将 `react-dropzone` 的 `file-too-large`
错误映射为项目中英文文案，并以格式化后的 MB 上限显示。其他拒绝原因保留现有行为。

图片压缩页上传提示改为说明“本地处理最高 250 MB”，避免继续显示固定 50
MB。服务端不可用提示说明当前账号的服务端额度，不引导用户上传后再失败。

### 内存与失败处理

大文件本地压缩仍需将图片解码到浏览器内存，实际内存占用主要由像素尺寸而不是文件字节数决定。若浏览器因图片尺寸、Canvas 上限或内存不足导致处理失败，沿用现有单文件失败状态和重试流程，不自动上传服务器。

## 影响范围

- 图片压缩页：本地上限、服务端额度判断、处理方式选择与提示。
- `ModeToggle`：支持单独禁用服务端选项及显示原因。
- `FileDropzone`：本地化文件过大错误。
- 中英文 messages：大文件、本地上限和服务端额度文案。
- 共享额度与 API 限制不变。

## 测试

- 断言图片压缩本地上限为 250 MB。
- 断言超过服务端额度时推荐并强制使用本地模式。
- 断言不同会话套餐得到正确的服务端额度。
- 断言 `FileDropzone` 对文件过大错误显示本地化文案，而不是原始英文和字节数。
- 断言 `ModeToggle` 只禁用服务端按钮，并展示原因。
- 运行 Web 全量测试、格式检查和生产构建。

## 非目标

- 不提高游客、登录用户或付费套餐的服务端上传额度。
- 不修改其他图片、PDF、字体和文件管理工具的上传上限。
- 不承诺所有 250 MB 图片都能在所有设备上成功解码；浏览器可用内存和图片像素尺寸仍是运行时限制。
