# 任务资源预算设计

## 目标与范围

把图片、PDF、字体、AI 四个队列各自的数量限制升级为每个 Worker 进程共享的资源准入。任务下载前检查输入元信息并预留内存估算和计算权重；额度不足时保持 pending 并延后调度，不能消耗业务失败重试，更不能先调用收费 AI。单任务确定超限立即失败，前端提示缩小输入、减少页数或降低分辨率。

本轮沿用现有任务/API/schema，不改数据库、不打包、不合并主分支。复用当前隔离工作区。下列默认值与实现选择由执行者根据现有处理链路确定，可通过配置调整。

## 准入与生命周期

- `TaskResourceBudgetService` 只在 `TasksWorkerModule`
  提供一次，四处理器必需注入；并发数量仍是外层上限。
- 默认共享估算内存 1024
  MiB、计算权重 4。图片/字体/AI 权重 1，PDF/证件照权重 2。AI 全生命周期保留额度，避免付费后重新排队或重复生成；此保守策略可能降低吞吐。
- 先按真实使用顺序读取文件元信息，继续校验所属用户；累计输入默认 128
  MiB、最多 100 项。图库参考每项预留 20
  MiB。估算根据任务类型、输入字节和配置的像素/输出上限计算，不能仅按文件数量。
- 内存和计算权重原子准入，不允许持有部分额度等待扩容。预算不足调用 BullMQ
  `moveToDelayed(now + 2000..3000ms, token)` 后抛
  `DelayedError`，不写 processing/failed，不增加 attemptsMade。配置使单任务永远无法准入时直接
  `TASK_RESOURCE_LIMIT_EXCEEDED`。
- 执行包在 `try/finally`
  中释放额度。CPU 权重是调度估算，不是线程或核数的硬隔离。进程间不共享额度；多副本需按总物理资源配置。

## 执行边界

- AsyncLocalStorage 保存当前任务输入预算，FilesService 的任务下载改用流式计数，累计实际字节不能超过准入时声明值；记录过小不能绕过限制。普通 HTTP 下载保持原接口。流异常/超限/超时中止底层请求。
- 图库参考同样计入有界输入。图片在解码前读头并检查总像素：默认每张及一个任务累计 3200 万像素；动图计入所有帧。图片转 PDF 同样检查。输入像素上限用于估算预留，避免小压缩文件导致大解码。
- AI 上游 JSON 默认最多 48 MiB，生成图片最多 32
  MiB；base64 在解码前检查长度，URL 下载限制时间和实际流字节，资源超限不换源、不重试。参考图片按顺序归一，避免同时解码多张。
- PDF 输入按任务累计最多 500 页（包括重复读取）；PDF 转图片最多渲染 100 页，每页最多 1600 万像素，累计图片编码输出最多 64
  MiB。按页面 bounds 和 DPI 在 toPixmap 之前检查；page、pixmap、document 均 finally
  destroy，ZIP 输出也有界。
- 原生库、WASM、Office、OCR、ONNX、字体及 PDF 内部展开存在估算外成本。本轮不宣称硬 RSS/CPU/磁盘隔离；真正硬限制依赖独立 Worker 容器/cgroup。说明预算应低于容器可用内存并为模型/运行时预留空间。

## 验收

覆盖共享加权准入、临界额度、异常释放、资源忙时不下载/不处理/不耗重试、实际字节超声明及并发读取、超像素和 PDF 高 DPI 拒绝、原生句柄清理、AI 超限不重试。增加真实 Redis 调度验证（如本机可用）和真实图片/PDF 边界测试。完成全量测试、构建、lint、格式检查及 OpenAPI/client 同步后中文提交。

## 审查补充

- 所有应用显式 MuPDF 栅格分配都检查尺寸，包括 PDF 压缩、Markdown 标准化、CAD 底图；PDF 拆分/重排累计输出页数最多 500，拆分编码输出与 CAD 底图累计 64
  MiB，CAD ZIP 复用有界输出工具。
- AI 明确的 `WxH` 输出尺寸在准入时检查；`auto`
  和来源实际返回值仍在结果读取/解码前检查。证件照外部 AI 同样限制响应和掩膜，资源超限不转本地 ONNX 回退。
- Office 文件存在检查使用 stat，实际产物以有界流读取；资源超限不重新启动转换器。仍不限制外部进程自身的峰值内存和临时磁盘。
- 预算以配置的像素上限保守预留，不在持有输入时等待追加资源；吞吐可能低于旧并发配置。资源延期使用抖动，不承诺严格 FIFO 或最大等待时长。
