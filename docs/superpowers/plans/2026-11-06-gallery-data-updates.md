# 图库加载与数据更新实施计划

**目标：**
降低试衣页面未使用图库的加载成本，让后台素材更新可被发现，同时避免任务操作导致无关静态数据反复刷新。

**依据与设计：** 用户要求实施 P2「优化图库加载与数据更新」。沿用 React
Query、现有全量元数据接口与前端分组分页；默认上传流程不请求图库，进入人像/灵感模式或主动打开可选图库后才加载。完整元数据仍用于跨视角分组、全局搜索和分类计数，不引入另一套分页协议。

**缓存策略：**
图库、模板、模型从任务缓存命名空间移出。图库和模板缓存 5 分钟，已启用查询在前台每 5 分钟检查更新，过期后聚焦/重连重新获取；请求携带 AbortSignal。图库提供刷新入口；更新失败保留旧列表和选择并提示重试。成功返回的权威列表中缺失的已选素材清除并提示，任务侧仍独立校验素材许可与可用状态。

**服务端策略：** 列表查询显式投影展示字段，不读取原图存储地址和无关管理字段；响应使用
`Cache-Control: public, max-age=0, must-revalidate`，由 Express
ETag 与浏览器条件请求处理未修改响应。每次校验读取数据库，不增加进程内长期缓存，因此导入、下架和删除不依赖额外失效脚本。接口 JSON 形状不变，无 schema 迁移。

**约束：**
中文文档和提交；双语 UI；测试在同级 test/；不升级版本、不打包、不合并或推送。复用现有隔离 worktree，基于 c8a1bcd 建立 codex/gallery-data-updates。

## 审查关注点

- 语言切换和请求取消不会将旧语言数据覆盖到新查询。
- 首次加载失败与后台刷新失败明确区分，空列表仍可刷新。
- 数据缩减后页码有效，选中素材下架后不能提交旧 ID。
- 可选图库按需加载，服饰与风格共用一次请求，上传流程不被图库故障阻塞。
- 创建、重试、删除任务仍刷新业务数据，但不触发图库、模板或模型请求。

## 实现取舍

- 沿用全量元数据和客户端分页，避免拆散多视角姿势或改变搜索、分类总数语义；本轮降低无需求加载、重复失效与重复传输，未引入服务端搜索分页协议。
- 已加载且启用的图库每 5 分钟检查更新；手动刷新立即请求校验。后台故障可暂时保留旧展示，但服务端任务仍重新校验素材可用性。
- 无数据库迁移，无新依赖，不打发布包。分支保留待后续集成，不自动合并或推送。
