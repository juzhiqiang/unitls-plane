# Utils-Plane 性能优化设计

## 目标

降低任务状态轮询、文件处理、列表查询和前端重依赖带来的资源放大，保持现有认证、任务状态和文件访问语义不变。

## 范围

第一批处理 P0/P1：

1. 任务状态接口增加有效保护，并提供批量状态查询，前端批量轮询且使用动态退避。
2. 文件和任务列表增加与过滤/排序匹配的索引，列表 API 增加基于时间和 ID 的 cursor 分页，同时兼容现有 page/limit 调用。
3. 上传、下载和缩略图链路减少不必要的整块复制；保留现有大小限制和响应格式。
4. 对 `pdf-lib`、PDF.js、字体解析和 ONNX Runtime 做页面级动态加载，降低普通工具页首屏包体。

第二批暂不实施：

- 拼图尺寸探测与渲染之间的解码复用。
- PDF 缩略图虚拟列表和更细粒度的浏览器内存预算。

## 架构方案

### 状态查询

新增
`GET /tasks/status?ids=<uuid>,...`，一次返回多个任务的轻量状态。接口仍允许匿名访问，以兼容现有任务流程，但必须恢复基于 IP 的节流；单次最多接受 100 个 ID，响应只包含状态、进度、输出文件 ID 和错误字段。单任务
`GET /tasks/:id/status` 保留兼容性并纳入节流。

前端任务组 hook 优先调用批量接口；单任务 hook 保持原接口。轮询间隔使用 1s、2s、3s、5s 的上限退避，进入终态立即停止，页面切到后台时暂停。

### 列表与索引

为 files 增加活动文件和回收站查询所需的部分索引，为 tasks 增加常用用户/状态/类型组合索引。新增 cursor 参数时以
`createdAt` 和 `id` 作为稳定排序键；旧 page/limit 参数继续可用，便于渐进迁移。

### 文件 I/O

优先使用 SDK 返回的流直接写入响应或传给 Sharp；无法流式处理的处理器继续使用 Buffer，但不得额外复制同一完整对象。上传端先保留 Multer 现有边界，避免一次引入临时文件清理和异步对象状态迁移；在本批中加入内存监控点和明确的并发预算配置。

### 前端加载

保持公共 layout 不引入重依赖。将仅用于交互/预览的解析器改为
`import()`，并确保动态模块在 SSR 期间不会执行。使用构建产物比较优化前后的 First Load
JS，不改变工具功能。

## 错误与兼容性

- 批量状态查询中单个不存在的任务返回对应的 `not_found` 状态，不让整个批次失败。
- 超过 100 个 ID 返回 400；重复 ID 去重后再查询。
- cursor 无效返回 400；缺省 cursor 继续使用现有第一页语义。
- 流式响应发生错误时正确销毁 stream，并保留现有 HTTP 状态码。
- 所有新增 API DTO 同步 Swagger、OpenAPI client 和中英文文案（如有用户可见文案）。

## 测试策略

- 先为批量状态、退避和 cursor 分页写失败测试，再实现。
- 为索引迁移增加 schema/migration 测试，并使用 PostgreSQL `EXPLAIN` 做手工验证。
- 为流式下载/缩略图增加 stream 生命周期和错误释放测试。
- 运行 Web/API/package 测试、lint、构建；记录构建体积变化和已知环境限制。
