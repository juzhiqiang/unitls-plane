# 文件删除完整生命周期优化

**目标：** 补齐永久删除的缩略图清理、失败恢复和历史残留回收，避免原图删除后缓存长期留存。

**授权与范围：** 用户选择 P1「补齐文件删除的完整生命周期」并要求实施。复用现有工作区，在
`codex/file-deletion-lifecycle`
分支执行；使用现有 NestJS、Drizzle、MinIO 和 BullMQ，不调整 24 小时匿名文件与 30 天回收站保留期。

## 设计决定

- 软删除只进入回收站，保留原图和缩略图以支持恢复。重复软删除不重置原始删除时间。
- 永久删除先领取现有 purge 租约，再删除原图及 `thumbnails/<fileId>/`
  下全部缓存版本，最后删除数据库记录。永久删除被接受后始终保留 purge 标记直到完成，不能恢复到缺少原图的状态。
- 定时清理接续所有带 purge 标记的文件，包括未进入回收站的业务硬删。硬删遇到有效租约必须报告未完成，不能让上层会话或账号提前删除关联记录。
- 缩略图冷生成在写缓存前及写入后核对文件状态；发现已开始永久删除时不写入或补偿清理。跨进程崩溃及旧版本残留由定期巡检兜底。
- 新增每日缩略图巡检，一次只扫描 100 个对象并分页续跑；只处理符合应用缩略图命名规则且权威数据库中已无对应文件的对象。保留仍在回收站的缓存。巡检不会扫描或清理其它对象前缀。
- 账号注销使用文件服务的硬删除入口；先检查任务，再清文件，所有文件完成后才删除账号记录。
- 不变更公开 HTTP 协议或数据库 schema，不新增依赖。导出 OpenAPI 验证漂移；不执行用户真实数据清理或生产任务。

## 审查重点

1. 原图已删除而缩略图失败后不能恢复文件。
2. 后台扫描不能删除有效文件或回收站文件的缩略图。
3. 缩略图上传晚于永久删除时应补偿；进程崩溃由巡检收敛。
4. 硬删租约被占用不能当作已完成，后台能接续非回收站文件。
5. 分页不会无限循环，单对象故障不会阻塞整批其它对象。

## 执行记录

- 基于已合入 main 的 `1baf6bb`；当前工作区已有依赖，无需重新安装。
- 根因：永久删除只调用原文件的 DeleteObject；缩略图注释明确暂不清理。账号注销绕过文件服务；cleanupTrashed 仅选择 deletedAt 非空的行，遗漏业务硬删留下的 purge 标记。
- 设计检查未发现阻塞事项。相互依赖的删除、缓存生产、后台巡检和注销一起验证并提交，避免中间提交只完成一部分生命周期。
- 审查修复：MinIO 删除分页增加已见游标检测，A→B→A 在第三次列表时终止；非回收站硬删失败保留意图。进一步确认 HEAD=true 无法排除超时 DELETE 稍后提交，因此统一永久删除接受后不可恢复，后台重试直到完成；代价是存储持续拒绝删除时文件保持不可访问，需要修复存储配置后续跑，符合永久删除语义。
- S3
  bucket 版本化场景不在本次应用对象清理保证内：这里只删除当前对象及不同缩略图版本键，不承诺擦除 bucket 历史版本。账号注销失败后的完整账号记录删除仍由用户重试；后台接续已标记文件，不新增账号注销调度协议。
