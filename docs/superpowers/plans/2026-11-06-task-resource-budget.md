# 任务资源预算实施计划

> 执行方式：使用 executing-plans 在当前隔离工作区逐项实现，完成后进行独立审查。

**目标：** 下载前按资源预算调度四类任务，并限制实际输入、图片解码及 PDF 渲染消耗。

**架构：**
Worker 单例加权准入服务，AsyncLocalStorage 传递当前任务的有界读取上下文；处理器统一在处理前准入并 finally 释放，资源错误保持不可重试语义。

**技术栈：** NestJS、BullMQ、Bun、Sharp、MuPDF。

**设计：** [任务资源预算设计](../specs/2026-11-06-task-resource-budget-design.md)。

## 全局约束

中文文档与提交；测试位于 API/Web 的 test 目录；沿用 API 与数据库契约；不合并、推送或发布。内存默认 1024
MiB、计算权重 4、输入 128 MiB、图像 3200 万像素、PDF 单页渲染 1600 万像素，均为每进程配置。

## 审查重点

- 资源延期不能当作业务失败处理，真实 BullMQ attemptsMade 不变。
- 文件元信息低报、重复输入及图库参考不能绕过累计预算。
- 并行读取发生异常时不能提前释放额度让其它任务抢占仍在使用的内存。
- 原生句柄和下载流在错误路径也须释放。
- AI 付费请求之后发现资源超限不能重新生成或换源。
