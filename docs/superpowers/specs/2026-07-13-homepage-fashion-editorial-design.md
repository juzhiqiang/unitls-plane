# 首页时尚编辑风视觉重构设计

## 目标

将 Utils Plane 首页从“赛博处理面板 + SaaS 卡片矩阵”重构为统一的时尚品牌编辑风页面。首页需要在首屏建立鲜明品牌识别，同时保留真实工具入口、处理边界说明和登录后的商业能力承接。

## 设计定位

首页采用“数字编辑部”视觉语言，不直接模仿某个品牌：

- 品牌气质：冷静、精确、克制，有时尚杂志的版式张力。
- 产品表达：工具不是功能清单，而是一组经过编排的文件处理作品。
- 视觉基调：黑、骨白、银灰为主，只使用少量酸性黄绿作为动作提示。
- 动态原则：Three.js 表现玻璃、金属和纸张材质，运动缓慢连续；不使用扫描线、HUD 网格、数据光束或高速旋转。
- 转化原则：首屏保留两个明确 CTA，后续区块保留四个高价值工具入口和工作台入口。

## 信息架构

### 1. 品牌首屏

首屏使用舞台式满幅构图，而不是左右两张卡片拼接：

- 左上为小型刊号与品牌说明，例如 `UTILS PLANE / EDITION 01`。
- 主标题使用两行编辑衬线体，中文文案为“让文件 / 更有形”。英文对应为“Shape / Every File”。
- 副文案解释图片、PDF、文档和字体可在本地或服务端完成处理，不使用“进化”“核心”等抽象技术口号。
- Three.js 场景位于首屏中央偏右，画布无卡片边框，作为环境的一部分。
- CTA 使用一个实心主动作和一个文字式次动作，避免按钮组像后台系统。
- 首屏底部保留一行处理承诺：本地优先、重任务可交给服务端、结果可预览、失败可恢复。

### 2. 精选工具目录

用杂志目录式两栏版面替代四张功能卡：

- 左侧为区块标题、说明和页码。
- 右侧为四条工具目录，每条包含编号、工具名、简短描述和箭头。
- 桌面端通过分栏、细线和大编号建立节奏；移动端按单列排列。
- 工具入口仍为图片压缩、长图拼接、Markdown / Word 转 PDF、GIF / APNG 制作。

### 3. 处理方式叙事

使用三段横向编辑内容说明产品边界：

- `01 本地处理`：适合浏览器完成的任务不必上传。
- `02 服务端能力`：重任务、任务记录和账户文件由登录能力承接。
- `03 结果可控`：预览、下载、重试和失败恢复保持可见。

该区域不使用重复卡片。每段通过大号序号、细线分隔和短文案形成杂志栏目。

### 4. 结尾工作台入口

结尾使用一块骨白色反差区域：

- 大标题强调“从下一份文件开始”。
- 一句说明把处理、预览、记录和恢复串成连续工作流。
- 提供“进入工作台”主动作。
- 使用一个静态或低速材质圆盘作为视觉收束，不再出现新的卡片结构。

## 视觉系统

### 色彩

- 深色背景：`#0A0A0A`
- 主文字：`#F1F0EA`
- 次级文字：`#9A9992`
- 骨白反差面：`#E9E6DD`
- 反差面文字：`#141414`
- 细线：白色 12% 或黑色 16%
- 唯一强调色：`#D7FF3F`

强调色只用于页码、状态点、主 CTA 的小面积反馈和 Three.js 材质边缘，不铺成大面积绿色背景。

### 字体

- UI、导航、标签和正文继续使用 Geist Sans。
- 首页主标题和区块大标题使用编辑衬线栈：`Iowan Old Style`、`Baskerville`、`Times New Roman`、`Songti SC`、`STSong`、`SimSun`、serif。
- 中文标题使用正常字距，不做负字距；英文标签可使用小型大写和有限字距。
- 首屏标题桌面端控制在 72-104px，移动端 52-64px，使用固定断点，不按视口连续缩放。

### 版式

- 首页专用最大宽度为 1440px，左右边距桌面 48-72px，移动端 20px。
- 圆角最多 4px；首屏 Three.js 画布无圆角、无边框。
- 不使用卡片套卡片、厚重阴影、渐变光球、扫描线或全屏网格。
- 分区主要通过留白、细线、反差底色和排版层级区分。

## Three.js 场景

### 构成

- 中央主体为半透明玻璃圆盘或扭转环体，表现“文件被重新塑形”。
- 周围保留 4-5 个薄片，材质接近纸张、磨砂玻璃和拉丝金属，不再绘制 PDF/GIF/DOC 终端卡片。
- 使用一盏柔和主光、一盏银灰轮廓光和极弱强调色边缘光。
- 场景背景透明，与页面背景自然融合。

### 运动

- 主体仅做低速呼吸和轻微偏转，不做持续累计的快速自转。
- 指针只产生小范围视差，最大旋转角度受限。
- 页面隐藏时停止动画；恢复时重置时钟，不追赶隐藏时间。
- `prefers-reduced-motion` 下渲染静态构图。
- WebGL 初始化失败时保留 CSS 材质海报，不影响文案和 CTA。

## 组件边界

- `page.tsx`：只负责区块编排、翻译读取和工具数据传入。
- `hero-workbench-scene.tsx`：负责 Three.js 生命周期、渲染和静态回退。
- `hero-workbench-scene-model.ts`：负责材质片配置和受限动画时钟。
- `homepage-quick-tools.tsx`：改为编辑目录列表，不引入新的工具数据源。
- `globals.css`：新增首页专用 token 和区块样式；不改变工作台组件的全局视觉行为。
- `zh.json` / `en.json`：同步维护首页品牌文案和元数据。

## 测试与验证

- 文案测试校验中英文标题、工具叙事和商业能力描述同步。
- 场景模型测试校验元素数量、动画时间上限和隐藏页恢复行为。
- 运行 `bun run test` 与 `bun run build`。
- 在 1440x900、1024x768、390x844 三个视口核对首页截图。
- 截图统一输出到 `artifacts/screenshots/`。
- 桌面与移动端检查标题换行、CTA 可见性、Three.js 非空、工具目录可点击、区块无重叠。

## 验收标准

- 首屏不再出现扫描线、终端网格、HUD 标签或独立卡片式 Three.js 容器。
- 中文标题明显区别于应用内 Geist UI 字体，具备编辑衬线气质。
- 页面只保留一个强调色，黑、骨白、银灰占据主要视觉比例。
- 四个高价值工具入口均可从首页直接进入。
- 登录与后续商业能力通过服务端能力文案表达，不承诺全部功能永久免费。
- 动画从后台恢复时不会高速追赶，低动态偏好与 WebGL 失败均有可用回退。
- 首页各区块在桌面和移动端形成同一套编辑版式语言。
