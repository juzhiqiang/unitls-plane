# Utils-Plane 公开免费公测完善设计

## 背景

Utils-Plane 已具备图片、PDF、字体、证件照、文档转 PDF、文件管理和异步任务等完整工具平台能力。当前主要问题不是工具数量，而是文件生命周期、账号数据权利、公开法务页面、运行诊断、产品表达和发布验证尚未形成一致的公测闭环。

本设计面向一次性完整改造版本。版本目标是完善现有 IP + HTTP 环境下的受限免费公测体验，不接支付，不宣称达到正式公网安全上线标准。

## 已确认决策

- 上线形态：公开免费公测，不接支付。
- 法务主体：`Utils Plane 项目团队`。
- 支持邮箱：通过 `NEXT_PUBLIC_SUPPORT_EMAIL` 配置。
- 遥测：前后端均不启用错误追踪、行为分析或 Session Replay。
- 账号注销：用户确认后立即永久注销，不设置冷静期。
- 数据导出：提供包含账号资料、任务记录和实际文件的完整 ZIP。
- 部署入口：保留当前 `5005/5006` 和 IP + HTTP 方式，定义为受限公测。
- 资源配额：不新增总存储、每日任务或并发配额。
- 发布门禁：只提供本地统一命令，不新增 GitHub Actions。
- 交付方式：一次性完整改造，内部按依赖顺序设置检查点。

## 明确不在范围内

- 不新增匿名文件或匿名任务访问令牌。
- 不调整 `/tasks/:id/status` 的现有访问方式。
- 不修改生产 Compose 网络、端口、默认密钥或匿名桶策略。
- 不接入 HTTPS、域名网关或自动证书。
- 不实现支付、订阅、订单、Team 空间或私有部署授权。
- 不新增存储总量、每日任务数、并发数或队列优先级配额。
- 不新增云端 CI。

上述边界意味着现有明文传输、默认生产凭据、匿名桶和公开任务状态风险仍然存在。本次版本只能称为受限公测，隐私政策、公测说明和部署文档不得把这些未处理项描述为已经解决。

## 总体架构

本次新增或调整四个独立边界：

1. `FilesService` 和 `CleanupProcessor` 负责文件生命周期。
2. 新增 `AccountModule` 负责账号汇总、完整导出和立即注销。
3. Web 公开路由负责隐私政策、服务条款和公测说明。
4. `HealthModule` 和根目录发布脚本负责运行诊断与本地发布验证。

现有图片、PDF 和字体处理器不承担账号注销、ZIP 导出或清理调度逻辑，只通过现有文件和任务记录参与这些流程。

## 文件生命周期

### 匿名活动文件

匿名文件继续在上传时设置 `expiresAt = createdAt + 24 小时`。清理条件为：

```text
userId IS NULL
deletedAt IS NULL
expiresAt IS NOT NULL
expiresAt <= now
```

清理成功后同时删除 MinIO 对象和数据库记录，不再把已删除对象的记录移动到回收站。

### 回收站文件

账号文件进入回收站时继续写入 `deletedAt`。永久清理条件为：

```text
deletedAt IS NOT NULL
deletedAt <= now - 30 天
```

回收站规则适用于所有带 `deletedAt` 的文件记录。匿名文件正常情况下不会进入用户回收站。

### 清理执行语义

- `CleanupScheduler` 每小时注册一个稳定的重复任务，避免应用重启产生重复调度项。
- `CleanupProcessor` 分别调用匿名过期清理和回收站清理。
- 每个文件独立处理；单个对象失败不终止整批。
- MinIO 对象不存在视为幂等成功，随后删除数据库记录。
- MinIO 删除失败时保留数据库记录，等待下一轮重试。
- 返回和日志记录扫描数、成功数、失败数和文件 ID，不记录文件名或文件内容。
- 测试固定系统时间，直接验证边界前、边界时和边界后的查询行为。

## 账号数据模块

新增 `AccountModule`，提供账号汇总、导出和注销。所有接口使用现有认证 Guard，仅允许操作当前登录账号。

### Dashboard 汇总

`GET /account/summary` 返回：

- 活动任务总数：`pending + processing`。
- 失败任务总数。
- 当前活动文件总数。
- 当前活动文件总字节数。
- 最近 5 条任务。
- 最近 5 个活动文件。

Dashboard 不再从最近 5 条记录推算全量计数。存储卡片展示真实文件总量和字节数，但不显示不存在的配额百分比。

### 完整数据导出

`GET /account/export` 直接流式返回 ZIP，不在本地磁盘或 MinIO 生成导出副本。

ZIP 结构：

```text
utils-plane-export-YYYYMMDD-HHmmss.zip
├── profile.json
├── tasks.json
├── files.json
└── files/
    ├── <安全文件名>
    └── <重名时带文件 ID 后缀的安全文件名>
```

- `profile.json` 只包含用户可理解的资料，不导出密码哈希、Session、OAuth token 或内部认证字段。
- `tasks.json` 包含任务类型、状态、参数、时间、输入和输出文件引用。
- `files.json` 包含文件 ID、原文件名、大小、MIME、创建时间、删除时间和导出路径。
- 活动文件和回收站文件均导出；清单明确标记状态。
- 开始发送 ZIP 响应前，使用对象 head 请求预检全部文件；任何对象缺失或不可读时拒绝导出，避免把不完整归档描述为完整导出。
- 文件从 MinIO 读取后直接写入 ZIP 流，按顺序或低并发处理，避免无配额账号造成内存峰值。
- 预检通过后若流式读取仍失败，则终止响应，使客户端无法得到看似成功的归档；客户端中断下载时终止后续对象读取，不留下导出副本。

### 立即注销

`DELETE /account` 请求体必须包含与当前账号一致的邮箱。服务执行顺序：

1. 查询账号全部文件记录。
2. 删除对应 MinIO 对象；对象不存在视为成功。
3. 所有对象处理成功后开启数据库事务。
4. 显式删除用户任务和文件记录。
5. 删除与邮箱相关的 verification 记录。
6. 删除 Better-Auth account 和 session 记录。
7. 删除 user 记录。

对象存储和 PostgreSQL 无法共享事务，因此数据库删除仅在全部对象删除成功后开始。若对象删除中途失败，用户和数据库记录保留；已经删除的对象在重试时按幂等成功处理。

注销成功后，Web 清理认证状态和 React Query 缓存并返回首页。失败时展示可重试错误，不显示部分成功或注销成功。

## 公开信任页面

新增以下 locale-aware 公开路由，并加入中间件公开路径：

- `/[locale]/privacy`
- `/[locale]/terms`
- `/[locale]/beta`

### 隐私政策

隐私政策至少说明：

- 浏览器本地处理与服务端处理的区别。
- 账号资料、认证 Cookie、文件和任务记录的用途。
- 匿名文件 24 小时和回收站 30 天保留规则。
- 数据导出和立即注销入口。
- 当前不使用行为分析、错误追踪或会话回放。
- 证件照 AI 模式启用时，图片可能发送给部署方配置的兼容服务提供商。
- 当前 IP + HTTP 环境不适合上传敏感文件。
- 运营主体和支持邮箱。

### 服务条款

服务条款至少说明：

- 服务处于免费公测阶段。
- 用户对上传内容和使用权限负责。
- 禁止违法、侵权、恶意消耗资源或攻击行为。
- 服务可能中断、调整或终止公测能力。
- 文件处理结果需要用户自行复核。
- 账号注销和违规账号处置规则。
- 运营主体和支持邮箱。

### 公测说明

公测说明使用用户语言描述：

- 当前免费能力和登录增强能力。
- 不承诺永久免费的功能范围。
- 已知部署限制，尤其是 IP + HTTP。
- 数据保留规则和建议上传内容。
- 问题反馈方式。

`NEXT_PUBLIC_SUPPORT_EMAIL` 在开发环境未配置时使用 `support@utils-plane.local`。生产发布验证必须要求该变量为有效的非 `.local` 邮箱，避免发布不可联系的法务页面。

### 页脚和公开导航

- 页脚使用 locale-aware `Link` 指向隐私、条款和公测说明。
- 支持邮箱使用 `mailto:`。
- 删除当前无真实页面的 `/docs` 和 `/github` 链接。
- 未登录用户访问三个公开页面不得被重定向到登录页。

## 无遥测策略

本次完全移除现有 Error Tracker 集成：

- Web 初始化组件和 Session Replay。
- API 初始化与配置 helper。
- 根目录、Web 和 API 的 SDK 依赖。
- sourcemap 上传脚本。
- Error Tracker 环境变量和文档。
- Docker 的外部 SDK build context。
- 仅服务于该集成的测试和构建逻辑。

普通业务日志、任务状态和健康检查不视为遥测，但不得记录文件内容、密码、认证 token 或第三方 API 密钥。

## 公测权益表达

权益实现继续保留 `free`、`signed_in`、`pro` 等内部计划类型，为未来演进保留兼容性。本轮只调整用户可见表达：

- `商业版` 改为 `登录增强能力`。
- `商业版选项` 改为 `公测增强选项`。
- `未来付费体系` 等内部规划语言改为当前可获得的具体收益。
- 设置页 `free` 显示为 `免费公测`。
- 不新增价格、升级、购买或套餐比较入口。

## PWA 安装体验

- 移除全局首次访问自动弹出的安装提示。
- 保留 `beforeinstallprompt` 捕获能力，但只在设置页浏览器支持时显示“安装应用”命令。
- 安装命令使用中英文消息，不显示硬编码英文。
- 浏览器不支持或应用已安装时不显示该命令。

## SEO

为每个具体工具提供独立的：

- `title`
- `description`
- `canonical`
- `hreflang` 和 `x-default`

工具元数据继续以 `tool-metadata.ts` 和双语消息为事实来源。客户端工具页通过同目录轻量 server layout 或 server page wrapper 输出 metadata，不复制业务逻辑。

Sitemap 收录：

- 首页。
- 图片、PDF、字体分类页。
- 所有唯一工具 href。
- 隐私、条款和公测说明。

Sitemap 不收录登录、注册、Dashboard、文件、任务和设置页。Robots 明确禁止工作台和认证相关页面索引。

## 运行诊断

### Liveness

`GET /health/live` 只证明 API 进程可响应，返回：

- 状态。
- release。
- commit。
- 构建时间。
- 启动时间。

### Readiness

`GET /health/ready` 并行检查：

- PostgreSQL：轻量 `SELECT 1`。
- Redis：`PING`。
- MinIO：bucket head 请求。
- BullMQ：读取各队列 job counts。
- LibreOffice：解析可执行文件路径或执行轻量版本检查。

PostgreSQL、Redis、MinIO 或 BullMQ 失败时返回 `503`。LibreOffice 缺失返回 `degraded`，不阻断其他工具。响应只暴露组件状态和耗时，不返回内部地址、桶名、凭据或原始错误栈。

现有 `/health` 保留为兼容摘要，可转为调用 liveness/readiness 的简化结果。


执行顺序：

3. 共享包测试。
4. API 测试。
5. Web Vitest。
6. OpenAPI 导出和 API Client 生成漂移检查。
7. 生产构建。
8. Playwright 公开路由和 SEO smoke。

工程调整：

- 增加 API 标准 `test` 脚本。
- 根目录测试命令不再让 Bun runner 直接执行 Vitest 测试。
- 配置跨平台换行策略，修复 Windows CRLF 导致的 Prettier/Lint 假失败。
- 不进行与本次触碰范围无关的全仓格式化。
- Playwright smoke 验证首页、工具页、隐私、条款和公测页公开可访问，工作台仍要求登录，工具 canonical 指向自身。

## 测试策略

### 文件生命周期

- 匿名文件在 24 小时前不清理、边界时清理、边界后清理。
- 回收站文件在 30 天前不清理、边界时清理。
- MinIO 对象不存在时仍删除数据库记录。
- MinIO 删除失败时保留记录并继续处理其他文件。
- CleanupProcessor 实际调用两条清理流程。

### 账号数据

- 汇总接口返回全量计数和最近记录。
- ZIP 包含 profile、tasks、files 清单和实际对象。
- 重名和不安全文件名得到稳定安全路径。
- 导出不包含密码、Session 或 OAuth token。
- 邮箱不匹配时拒绝注销。
- 对象删除失败时不删除数据库用户。
- 全部对象成功后显式清理任务、文件和认证数据。
- 重试注销保持幂等。

### 公开页面和 SEO

- 三个公开页面中英文消息完整。
- 中间件允许匿名访问。
- 页脚没有失效内部链接。
- PWA 提示不再全局自动显示。
- 工具 metadata 和 sitemap 覆盖全部唯一工具路由。

### 运行诊断

- 每个依赖检查的成功、失败和超时路径。
- 核心依赖失败返回 `503`。
- LibreOffice 缺失返回 `degraded`。
- 健康响应不包含敏感配置。

## 实施顺序与检查点

虽然作为一次版本交付，实施按以下顺序进行：

1. 修复测试命令和换行门禁，建立可用基线。
2. 实现生命周期和清理测试。
3. 实现 AccountModule、导出、注销和 Dashboard 汇总。
4. 移除遥测集成。
5. 实现公开页面、公测文案、PWA 和 SEO。
6. 实现健康检查。
7. 更新 OpenAPI、客户端类型和文档。
8. 运行完整发布验证和浏览器 smoke。

每个检查点必须在继续前运行相关测试，避免一次性版本把多个失败来源叠加到最后。

## 验收标准

- 匿名过期文件和 30 天回收站文件按规则永久清理，不误删未到期文件。
- 登录用户可以下载完整数据 ZIP，并可通过邮箱确认立即注销。
- 隐私、条款和公测说明对匿名用户公开，中英文完整。
- 项目不再加载或构建任何 Error Tracker/Replay 代码。
- Dashboard 使用真实全量计数和存储数据。
- PWA 不在首次访问自动弹窗。
- 每个工具页具有自身 canonical 和描述，Sitemap 覆盖全部工具。
- 健康检查可以区分进程存活、核心依赖失败和 LibreOffice 降级。
- `bun run release:verify` 在本地可重复执行并通过。
- README、`.env.example`、`PROJECT_SPECS.md` 和部署文档与真实行为一致。
- 文档明确保留的 HTTP、默认凭据、匿名桶和任务状态风险，不宣称这些风险已解决。
