# 长任务体验与提交幂等性

## 目的

用户要求继续实施 P2 优化。网络短暂中断不应导致重复任务、重复消耗额度；页面离开或刷新后，应能找回已提交任务，区分服务端失败与浏览器停止等待。

## 实施选择

沿用 Next.js、React Query、NestJS、PostgreSQL 和现有任务 outbox，浏览器 SHA-256 显式复用锁文件已有的
`@noble/hashes@2.2.0`，兼容普通 HTTP 环境。这些具体实现选择由执行者根据现有架构确定。

- 创建与重新生成支持可选 UUID `Idempotency-Key`，旧客户端无 header 时保留现有行为。匿名携带 UUID
  `X-Task-Client-Id`，登录用户以服务端会话 userId 为准，按身份和 key 隔离。
- 独立 `task_submissions`
  表保存 key、scope、规范化请求的 SHA-256、taskId、创建及过期时间。保留 24 小时；同 key 同参数返回原任务，同 key 不同参数返回 409。对象属性顺序不影响比较，数组顺序保留。过期后可作为新提交。
- PostgreSQL 事务锁串行化同 scope/key 的请求；记录、任务和 outbox 同事务提交。重复请求在文件可用性与额度检查前返回。已删除任务的记录在保留期内返回 410，避免重建。用户注销级联删除记录。清理 worker 分批清理过期记录。
- 查询提交回执的公开端点使用相同身份 scope；查不到返回 404，已删除返回 410。仅返回回执对应的任务，不能用其它身份查询。
- 前端统一提交层对同一 hook 同参数的并发调用合并；传输失败或 5xx 最多自动重试两次，每次保持 key。业务 4xx 不自动重试。明确成功后下一次相同参数提交使用新 key，以保留连续多张生图的语义。
- sessionStorage 按账户/匿名浏览器会话存储提交 key、请求指纹、任务 id、类型和时间，绝不保存提示词、PDF 密码或文件内容。未确认提交通过回执查询找回，不自动提交新任务。记录最多保留 24 小时；存储不可用时在内存中继续工作。
- 应用内提供可收起的最近任务区，覆盖所有共享提交 hook 的服务端工具。刷新、切页后显示权威状态、真实耗时、断线提示、取回/重试下载。匿名用户也可找回本标签页任务。删除提示仅隐藏记录，不取消任务；不提供虚假的队列位置、预计完成时间或服务端取消。
- `waitForTask`
  支持 AbortSignal、有限等待、网络重试，超时携带 taskId，区别于任务失败。中止只停止客户端等待。共享图片处理流程传入 signal，并保留同一文件操作的已建任务，以便等待/下载重试复用。
- 任务状态回调在 StrictMode 和缓存命中时只触发一次。文案中英文同步。

## 边界

上传本身不是幂等协议的一部分；相同 File 的同时上传在单个 hook 中合并，已结束的独立上传仍允许新文件。提交回执可找回响应丢失的任务。刷新后不会恢复本地未上传文件或工具表单；可在最近任务区取回产物。保留窗口之外的历史由登录用户的任务列表提供。

## 验收

真实 PostgreSQL 并发提交只产生一个 task 和一个 outbox；跨用户/匿名 scope 隔离、参数冲突、回滚、额度重放、删除墓碑和过期行为有回归覆盖。前端覆盖网络重试保持 key、显式连续提交不合并、刷新恢复、身份切换、存储失败、等待超时与中止、下载失败仅重试下载。运行全仓测试、类型/构建、lint、格式检查，导出 OpenAPI 并更新客户端。完成后中文提交，不自动合并或推送。
